# 事實查核檢核清單：ant-pr-review × ant-peer-review

依兩個 repo 2026-10-26 的程式與規格整理。兩邊各存一份相同的檔案（`docs/FACTCHECK.md`），改動任一邊的查核行為時，兩份都要更新。兩邊的事實查核核心（`factcheck.py`）源自同一份程式，之後各自加了功能。

- **強制方式**：「程式」指會在程式碼裡擋下或改寫；「提示詞」指只寫在給模型的指示裡，模型可能不照做。
- **pr / peer**：✓ 有，— 沒有，△ 部分有。

## A. 抽取宣稱

| # | 檢查 | 強制方式 | pr | peer |
|---|---|---|:-:|:-:|
| A1 | 每位審查模型抽出可查證的宣稱，附錨點（句子編號）和類型 | 程式（schema） | ✓ | ✓ |
| A2 | 錨點相同、正規化後文字相同的宣稱合併為一筆，記下是哪些模型抽出的 | 程式 | ✓ | ✓ |
| A3 | 宣稱類型：日期、數字、法律、專有名詞、引述、其他 | 程式（列舉） | ✓ | ✓ |
| A4 | 「指控」和「法條引用」是獨立類型，會進入查核帳本 | 程式 | ✓ | — |
| A5 | 學術識別碼（DOI、arXiv）只在使用者開啟學術選項時才抽出並查證（pr 用 `--academic`） | 程式 | ✓ | ✓ |
| A6 | 多數模型判定的 S 曲線階段，會成為一筆待查宣稱 | 程式 | — | ✓ |

## B. 執行查證

| # | 檢查 | 強制方式 | pr | peer |
|---|---|---|:-:|:-:|
| B1 | 查證模型必須實際呼叫搜尋工具；沒搜尋就答「supported」，一律改成「無法查證」 | 程式 | ✓ | ✓ |
| B2 | 只引用本次搜尋或讀取結果裡出現的網址，不憑記憶引用；搜尋摘要只是線索，要讀全文找出支持的段落 | 提示詞 | ✓ | ✓ |
| B3 | 宣稱和上下文都當成不可信的資料，包在隔離區塊裡交給模型 | 程式 | ✓ | ✓ |
| B4 | 法條引用要查該法域的官方法規資料庫，核對條號和現行條文 | 提示詞 | ✓ | — |
| B5 | 只選能留下搜尋紀錄的模型當查證者；名單裡沒有時，不上網，直接記為「沒有可搜尋的模型」 | 程式 | ✓ | 不需要：peer 的模型都走 `claude -p`，都能搜尋 |
| B6 | 禁發中（禁運）的內容不上網查詢，記為「禁發」；學術識別碼查詢也一樣 | 程式 | ✓ | — |
| B7 | DOI 和 arXiv 直接查 doi.org、Crossref、arXiv 的 API，不經過模型 | 程式 | ✓ | ✓ |
| B8 | 已撤稿的論文記為不成立；引文標題和 Crossref 標題不符記為部分成立 | 程式 | ✓ | ✓ |
| B9 | API 回 HTTP 200 但沒有資料（或標題是「Error」），仍算「查無此識別碼」 | 程式 | ✓ | ✓ |

## C. 來源採信

| # | 檢查 | 強制方式 | pr | peer |
|---|---|---|:-:|:-:|
| C1 | 模型列的來源，必須真的出現在這次工具回傳的結果裡，否則丟掉 | 程式 | ✓ | ✓ |
| C2 | 不完整的網址、只有網域的網址，以及只出現在搜尋關鍵字裡的網址，都不算來源 | 程式 | ✓ | ✓ |
| C3 | 判為成立、部分成立或不成立，至少要有一個保留下來的來源，否則改成「無法查證：無來源」 | 程式（不得違反的規則） | ✓ | ✓ |
| C4 | 每個來源記下存取時間，報告在網址旁顯示日期 | 程式 | ✓ | ✓ |
| C5 | 來源分級：查證模型替每個來源標類型，程式核對網域。法規庫、法院、主管機關、登記資料、交易所公告在官方網域為 A；doi.org、arxiv.org 為 A，其他學術網站為 B；獨立媒體為 B；公司自述、彙整站、線索為 C；官方類型但網域不是官方的，降為 C。同一家媒體只算一個來源 | 程式（`sources/grade.py`，兩邊相同） | ✓ | ✓ |
| C6 | 每筆宣稱標強度：一個 A 或兩家不同媒體的 B 為「來源充分」，一個 B 為「單一來源」，只有 C 為「僅弱來源」，舊紀錄沒有類型為「未分級」；報告在來源前標 [A]／[B]／[C] | 程式 | ✓ | ✓ |

## D. 狀態與重試

| # | 檢查 | 強制方式 | pr | peer |
|---|---|---|:-:|:-:|
| D1 | 四種狀態：成立、部分成立、不成立、無法查證 | 程式（列舉） | ✓ | ✓ |
| D2 | 可重試的原因：離線、逾時、錯誤、未搜尋 | 程式 | ✓ | ✓ |
| D3 | 「禁發」「沒有可搜尋的模型」也可重試 | 程式 | ✓ | — |
| D4 | `--continue` 只重查待查和可重試的宣稱；查到一半停下時顯示進度（例如 18/30），讓你選之後繼續或直接定稿 | 程式 | ✓ | ✓ |
| D5 | 定稿時帳本沒變，就不產生新版報告；有變，產生下一版並附變更紀錄，不再呼叫審查模型 | 程式 | ✓ | ✓ |

## E. 查核結果如何影響判定

| # | 檢查 | 強制方式 | pr | peer |
|---|---|---|:-:|:-:|
| E1 | 依賴「無法查證」宣稱的發現另列「暫列」，不算進正式判定 | 程式 | ✓ | ✓ |
| E2 | 例外：本身就屬於「可證明性」的風險不會被另列，因為無法證明正是風險所在 | 程式 | ✓ | — |
| E3 | 辯論時，每位模型都看得到目前的查核結果 | 程式（提示詞內容） | ✓ | ✓ |
| E4 | 證據優先：帳本裡不成立的宣稱，即使有模型反對，也能確認紅線（pr 是捏造指控，peer 是幻覺）；但只靠 C 級來源的「不成立」不算證據，pr 列為弱證據，peer 列為警告 | 程式 | ✓ | ✓ |
| E5 | 專有名詞或譯名不符只發警告，不構成否決紅線的證據 | 程式 | — | ✓ |

## F. 輸出前的閘門

| # | 檢查 | 強制方式 | pr | peer |
|---|---|---|:-:|:-:|
| F1 | 報告檢查：模型自稱「我已驗證／執行過」會被標出；不可留占位文字 | 程式 | ✓ | ✓ |
| F2 | 「沒找到」的錨點必須寫出查過哪些部分 | 程式 | ✓ | ✓ |
| F3 | 修訂稿裡，帳本無法支持的指控如果原句還在，就刪掉並告知 | 程式 | ✓ | — |
| F4 | 撰稿時每一句宣稱都要登記依據和分類（可公開、內部、不可主張、待驗證）；缺的事實留 `[待查證]` | 程式＋提示詞 | ✓ | △ 只有提示詞規定事實只能取自材料 |
| F5 | 稿子不得出現材料或簡報裡沒有的數字（pr 擋下匯出；peer 觸發一次重寫並在檢查表標為未通過） | 程式 | ✓ | ✓ |
| F6 | 可直接發布的稿子不得留有占位或「待驗證」宣稱 | 程式 | ✓ | — |

## G. 審查題中與查證有關的（pr 的檢核題，由審查模型逐題作答）

- **JOU-06：** 尚未確認的原因、範圍或保證；說「沒有報告」時要寫出依據範圍。
- **JOU-14：** 只是計畫中的行動，有沒有寫成已經做了。
- **JOU-17：** 能不能讓他人查核：第三方、原測試方、封存樣品；結論有沒有快過證據。
- **EXP-05：** 刊出前有沒有給對方回應的機會。
- **JOU-11：** 有沒有把混合了事實與評論的內容，整體標成「謠言」。
